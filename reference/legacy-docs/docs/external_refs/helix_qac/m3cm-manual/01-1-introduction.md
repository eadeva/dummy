1 | Introduction
The original MISRA C Guidelines were published in April 1998 by the Motor Industry Research Association in a
document entitled "Guidelines For The Use Of The C Language In Vehicle Based Software". In 2004, an updated version
of this document was published under the title "MISRA C:2004 Guidelines for the use of the C language in critical
systems". In July 2007, a Technical Corrigendum was issued to address a number of issues which required correction or
clarification. This was incorporated into the base document when MISRA C2 was reprinted in June 2008. In 2013, an
updated version of the MISRA C Guidelines was published under the title "MISRA C:2012 Guidelines for the use of the C
language in critical systems". There are therefore three versions of the guidelines currently supported by PRQA:
n MISRA C:1998 (MISRA C1).
n MISRA C:2004 (MISRA C2).
n MISRA C:2012 (MISRA C3).
MISRA C:2012 has subsequently been updated by four amendments and two technical corrigenda, and these revisions
have been consolidated into a single document published as MISRA C:2023
Throughout this document MISRA C:2023 will be referred to as MISRA C.
THE MISRA C Compliance Module
This document provides an introduction to the MISRA C Compliance Module (M3CM). The M3CM module is designed to
enforce compliance with the MISRA C programming standard in conjunction with Helix QAC for C.
Helix QAC for C is a software tool that performs static analysis on C source code. It is important to have it configured so
as to restrict the output of warning messages to those that are of particular concern. Selection of the M3CM component
in your Helix QAC projects configures Helix QAC for C to enforce compliance with the MISRA C coding guidelines.
Helix QAC for C is able to detect most of the statically detectable conditions identified in the MISRA C guidelines (as well
as many others). M3CM configures Helix QAC for C to identify issues which are specific to those guidelines, and
provides a cross-reference between the standard Helix QAC for C warning message(s) and the corresponding MISRA C
guideline. Also available is an HTML description of each guideline.
For some MISRA C coding standard guidelines that are not enforceable directly by Helix QAC for C, additional checks
are provided through M3CM secondary analysis. These checks are programmed using the analysis output files (.met)
generated by the Helix QAC for C primary analysis process.
Some MISRA C guidelines impose constraints on the complete system rather than the code in a single translation unit.
These requirements are enforced by the CrossModule Analysis capability of Helix QAC for C (enforced through the
RCMA component).
