Dataflow Configuration Option Precedence
Dataflow configuration options can be passed into both QAC/QACPP and Dataflow. However, their precedence changes
depending on their type.
Primary Options
The option passed into Dataflow takes precedence over the option passed into QAC/QACPP. If the type is a list rather
than single value, the QAC/QACPP values are first and the Dataflow values are appended. For example:
QACPP via
-nacs 1
-vml 1
-qx /A
-si /A
DF via
-nacs 2
-vml 2
-qx /B
-si /B
Dataflow would have the following values:
nacs: 2
vml: 2
qx: /A /B
si: /A /B
Prod Options
Here, the option passed into QAC/QACPP takes precedence over the option passed into Dataflow. If the type is a list
rather than single value, the Dataflow values are first and the QAC/QACPP values are appended. For example:

-prodoption df::branch_model_threshold
Syntax:
-prodoption df::branch_model_threshold=value
Default:
-prodoption df::branch_model_threshold=200
Category:
Advanced
Function:
Sets the maximum branch cardinality for exact modelling of variable interdependency.
Page 76


---
*Page 76*

Branch refers to:
n if statement
n && or || expression in an if statement
n case clause of a switch statement
When control flow merges nested branches, it is possible more than one branch will be merged simultaneously, e.g.
if (a)
// branch 1
{
if (b) // branch 2
{
}
// no statements following the 1st branch
}
// merge point for both branches
Due to tracking of variable interdependency, branch points that merge multiple branches are expensive for an SMT
solver to evaluate. Branch points with cardinality exceeding the value configured are modelled such that variable
interdependency is not tracked for the branches being merged. Therefore, at the expense of analysis accuracy,
performance of dataflow may be improved by setting a value lower than the default. Setting a value higher than the
default should be done with caution as it may cause excessive run time, message 2757 or a crash.
This option only applies when dataflow is enabled (-enabledataflow+).
See the Dataflow manual for more information.

This option enables the Dataflow cache. The df::cache_file parameter is also required, otherwise the functionality will not
be enabled.
The cache stores analysis data, which is accumulated over time by Dataflow. It is then used to improve the performance
of subsequent runs of Dataflow. This improvement can result in either a shorter Dataflow runtime or, if function timeouts
are used in the project, a reduction in function timeouts occurring.

Default:

Category:
Advanced
Function:
Specifies the Dataflow cache file for the Dataflow caching functionality.
This option specifies the file to use for the Dataflow cache. If the file does exist, the cache contents will be read into
memory by dataflow. If the file doesn't exist, it will be created and populated when dataflow exits. An additional lock file
will be created to handle parallel reads and writes to the cache file.

This option configures the function names and the related value pairs the result must be checked against. It is used in
combination with message 3535. This message checks whether the result of the specified function call has been
checked against the pair of values. If the result from the function has been compared to the first value, the result should
be compared to the second value as well.
For Example:
Using
-po df::fncall_result_checked=foo,A,B
enum STATUS_t { A, B, C };
enum STATUS_t foo();
void bar()
{
enum STATUS_t sts = foo();
/* expect: 3535 */
if (sts == A)
{
// Do processing
}
  sts = foo();
/* expect: !3535 */
if (sts == A || sts == B)
{
// Do processing
}

(starting from 1) of an out-parameter which stores the result, rather than the return value itself.

Default:

Category:
Advanced
Function:
Set an aggregate function timeout in milliseconds to limit the overall time spent in dataflow analysis for

This may curtail related results, and is designed to avoid lengthy analysis attempts on severely complex functions.
This option only applies when dataflow is enabled (-enabledataflow+).

component, then the value configured with the primary analysis component takes precedence.

-prodoption df::inter
Syntax:
-prodoption df::inter={0|1|2|3|4|5}
Default:
-prodoption df::inter=0
Category:
Advanced
Function:
Sets the maximum amount that a function will be allowed to grow by as a result of inserting called
function code into the caller as part of inter-function analysis.
The values applied have the following effect:
n Setting '-po df::inter=0' means that no function growth is allowed.
n Setting '-po df::inter=1' results in a maximum growth of 20.
n Setting '-po df::inter=2' results in a maximum growth of 200.
n Setting '-po df::inter=3' results in a maximum growth of 2,000.
n Setting '-po df::inter=4' results in a maximum growth of 20,000.
n Setting '-po df::inter=5' results in a maximum growth of 200,000.
A simplified statement refers to an internal deconstruction of source-level statements which includes expansion of
temporaries, deconstruction of compound statements according to sequence points, and other requirements of dataflow
examination. Therefore the number of explicit statements in a function will nearly always be less than the number of
simple statements.
With df::inter=5, if the expanded set of simplified statements exceeds the limit of 200,000 message 2756 is generated.
This option only applies when dataflow is enabled (-enabledataflow+).
See the Dataflow manual for more information.

-prodoption df::query_timeout
Syntax:
-prodoption df::query_timeout=value
Default:
-prodoption df::query_timeout=50
Category:
Advanced
Function:
Sets the maximum time in milliseconds an individual query is allowed to execute.
Queries are an internal part of the dataflow analysis system, and several queries are typically run for each type of
dataflow analysis performed. There can be many hundreds of queries performed for more complex functions.
Limiting the time spent on queries will cut short longer ones and may affect accuracy of results.
This option only applies when dataflow is enabled (-enabledataflow+).
Note: Some queries are cached in Dataflow to improve performance. Queries that timeout are also cached along with the
current query timeout value. As such, when the Dataflow query timeout value is increased, these cached timed out
queries will be re-run, to see if the increased time allows the solver to get an answer.
See the Dataflow manual for more information.

Syntax:
-forgetall option
Default:
no entry
Category:
Advanced
Function:
Resets previous configuration settings for option.
Some options are cumulative in their action in that successive usage of the option adds extra settings rather than
replacing the previous ones.
For example:
... -q path1 -q path2 -forgetall q -q path3 filename
For this argument list, the path1 and path2 options will be discarded and only path3 will be quieted.
The following options are cumulative in Dataflow:
n -nomsg,-no,-n
n -only,-o
n -quiet,-q

-intrinsictype,-it
Syntax:
-intrinsictype {size_t | ptrdiff_t | wchar_t | enum}=datatype
Default:
-intrinsictype "size_t=unsigned int"
-intrinsictype "ptrdiff_t=long"
-intrinsictype "wchar_t=unsigned char"
-intrinsictype "enum=signed int, unsigned int, signed long, unsigned long, signed long long,
unsigned long long"
Category:
Advanced
Function:
Determines the underlying type and semantics of built-in types during parsing.
Determines the type associated with the sizeof operator (size_t), the result of pointer subtraction (ptrdiff_t) and the
underlying type to use for enumerations. Allows wchar_t to be modelled as an alias to a type rather than a keyword and a
distinct type.
For -intrinsictype "size_t=...", -intrinsictype "ptrdiff_t=...", and -intrinsictype "wchar_t=...", a single built-in type name is
specified to use as the underlying type. Dataflow will generate a level 9 warning if these are not consistent with any
typedef settings encountered in the source code.
For -intrinsictype "enum=...", a sequence of basic data types is specified in a comma-separated list. For each enum
definition, Dataflow determines the minimum and maximum value of the enumerators used to define the enum type.
Starting with the first entry in this list, the first type large enough to hold all the enum's values will be selected as the
underlying type.

-virtualmemorylimit,-vml
Syntax:
-virtualmemorylimit value
Default:
-virtualmemorylimit 100
Category:
Advanced
Function:
Determines the limit on the available memory a component can utilise.
Before analysis is performed by a component a limit is set on the amount of memory that the component can utilise. By
default this limit is set to either a percentage of the systems physical memory or a default fixed size, whichever is largest.
This option determines the limit placed on the memory available to the component during analysis as a percentage of the
total systems memory.
If the argument of this option is 0 then no memory limit is applied to the component. And if the value of the argument does
not lie between 0 and 100 then the default limit will be applied.
