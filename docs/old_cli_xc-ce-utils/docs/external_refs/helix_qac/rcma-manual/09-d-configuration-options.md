-prodoption class::member_encapsulation_ratio
Syntax:
-prodoption class::member_encapsulation_ratio=ratio
Default:
no entry
Category:
Basic
Function:
Threshold setting for ratio between members and getters/setters.
When the member_encapsulation_ratio is specified, RCMA will calculate the ratio of members to public getters/setters. If
the actual ratio is larger than the specified ratio, then message 1760 will be generated.
The following formula is used to determine the ratio for a given class:
n n = Number of private or protected members.
n m = Number of private or protected members with a public Getter or Setter function.
ratio = ( m / n ) * ( 1 - 1 / sqrt(n) )
-prodoption close_name::any_case
Syntax:
-prodoption close_name::any_case[{+|-}]
Default:
-prodoption close_name::any_case-
Category:
Basic
Function:
Specifies that case is to be ignored when matching identifiers.
After the processing of the -prodoption close_name::similar and -prodoption close_name::ignore options (if specified),
any upper case characters in source code identifiers are changed to lower case.
For Example, with -prodoption close_name::any_case+ the following identifiers will be considered as similar:
int FOO;
int foo;

-prodoption close_name::sig_char
Syntax:
-prodoption close_name::sig_char=limit
Default:
no entry
Category:
Basic
Function:
Maximum length within which two identifiers must be unique, default value is 64.
If two source code identifiers do not differ within the number characters specified, then a diagnostic will be issued.
For example, with -prodoption close_name::sig_char=6 the following identifiers will trigger a diagnostic:
int abcdef1;
int abcdef2;
See also -prodoption close_name::sig_extern_char.

-prodoption close_name::similar
Syntax:
-prodoption close_name::similar='string1'[, 'string2' [, ..., 'stringn']]
Default:
no entry
Category:
Basic
Function:
Characters to be considered as identical when matching identifiers.
Each specified character in each set is mapped to a unique character value. If a character in a source code identifier
appears in the specified set then it is replaced with the unique character value for that set when matching identifiers.
The stringN options should be specified using JSON (JavaScript Object Notation).
For Example, with -prodoption close_name::similar=['O0'] the following identifiers will be considered as similar:
int FOO;
int F00;

-crossmoduleanalysisfile,-cmaf
Syntax:
-crossmoduleanalysisfile filename
Default:
no entry
Category:
Basic
Function:
Sets up the template to be used for the project-wide .arc and other output files.
Sets up both the prefix and the absolute path (or, alternatively, the path relative to the current directory) of the diagnostic
and metric output files generated by RCMA. Such output might take the form of .arc, .cma and .via files.
See the Cross Module Analysis I/O section of the RCMA user manual.

-forgetall,-forget,-f
Syntax:
-forgetall option
Default:
no entry
Category:
Advanced
Function:
Resets previous configuration settings for option.
Some options are cumulative in their action in that successive usage of the option adds extra settings rather than
replacing the previous ones.
For example:
... -q path1 -q path2 -forgetall q -q path3 filename
For this argument list, the path1 and path2 options will be discarded and only path3 will be quieted.
The following options are cumulative in RCMA:
n -nomsg,-no,-n
n -only,-o
n -quiet,-q

-prodoption init::functions
Syntax:
-prodoption init::functions= 'string1'[, 'string2' [, ..., 'stringn' [; ...']]]
Default:
-prodoption
init::functions=main,wmain,WinMain,wWinMain,DllMain,wDllMain,::main,::wmain,::WinMain,::wWinMain,::DllM
ain,::wDllMain
Category:
Basic
Function:
List of functions requiring initialization.
Configures RCMA to check that distinct pairs of functions are always called in the specified order.
Function pairs are created by combining the first function with subsequent names. For example, init1,func1,func2
will create the pairs "init1, func1" and "init1, func2".
The order in which these pairs are added is not significant. This analysis takes place for all program entry points (see -
po init::entry).
For example, in the following, RCMA will check that "init1" is called before "func1b" and "init2" before "func2":
-prodoption "init::functions=init1,func1a,func1b;init2,func2"
Fully qualified QA names should be used for C++. A wildcard of the form "@*" can be used to refer to members of
unnamed namespaces.

-nomsg,-no,-n
Syntax:
-nomsg message_number_list
Default:
no entry
Category:
Non-component
Function:
Suppresses the display and generation of the specified messages.
Message numbers can be specified individually, or as a list, range or a combination of both:
n -nomsg 2356
n -nomsg 1234,1236,1240
n -nomsg 2111,2200-2300
Note:
This option is only available at the file or directory level. The enabling or disabling of diagnostics at the
component level is managed through the Rule Configuration File (RCF).
This option is cumulative. See -forgetall,-forget,-f.

Syntax:
-only message_number_list
Default:
no entry
Category:
Non-component
Function:
Only the specified warning messages will be generated.
Message numbers can be specified individually, or as a list, range or a combination of both:
n -only 2356
n -only 1234,1236,1240
n -only 2111,2200-2300
Note:
This option is only available at the file or directory level. The enabling or disabling of diagnostics at the
component level is managed through the Rule Configuration File (RCF).
This option is cumulative. See -forgetall,-forget,-f.

-prodoption pal2::keep_ixx
Syntax:
-prodoption pal2::keep_ixx[{+|-}]
Default:
-prodoption pal2::keep_ixx+
Category:
Basic
Function:
Specifies that the intermediate output from .arc file processing not be removed.
Processing the output from the parser, especially for a large project, can be expensive. When an intermediate output is
present, the output from the parser is only processed a second time if its content has changed.
If disk space is an issue, then disabling this option will result in the intermediate .ixx files being deleted once they are no
longer required.

-prodoption qax::limit
Syntax:
-prodoption qax::limit=size(KB)
Default:
-prodoption qax::limit=30
Category:
Advanced
Function:
Sets the maximum packet size in KB sent to the QAX daemon.
The following information is sent by the analysis tools to the QAX daemon:
n Filenames
n Locations
n Preprocessor Events
n Diagnostics
n Annotations
n Function Flow Graphs.
This option controls the amount of data stored before being transmitted to the server.
In general this option does not need to be changed, however, if investigating a failure with the tool, it can be useful to set
the option to 0 in order that all data is sent immediately to the daemon.

Note:

-quietextended,-qx
Syntax:
-quietextended filename|path
Default:
no entry
Category:
Basic
Function:
Suppresses the generation of diagnostic output for unused contents of the specified file or files in the
specified path.
This will have the effect of suppressing warning messages as well as significantly reducing the size of the output
produced. This suppression is limited to constructs from those files/folders that are not used in non suppressed files.
When the argument is a non-absolute path, the path is interpreted to be a regular file path relative to a -systeminclude
path. If the concatenation of a system include path and the relative file path corresponds to an existing file, the option
takes effect on that file.
Note:
This option applies only to included files and has no effect on the main source file.
This option is cumulative, see -forgetall,-forget,-f.

-threshold,-thresh
Syntax:
-threshold metric{<|<=|=|>|>=}value[:[prefix_]msg_no]
Default:
no entry
Category:
Advanced
Function:
When specified, message msg_no is output whenever the threshold condition (from the set
{<|<=|=|>|>=} for specified metric is exceeded.
The metric is specified by the name that appears in the metrics records of the .arc file. There are no default values. If
:msg_no is omitted the default analyzer message 4700 will be used.
The optional prefix_ can be used to specify the Compliance Module that msg_no is associated with.
See Metric Thresholds and Metric Output File sections of the Helix QAC for C/C++ component manuals for more
information.

-virtualmemorylimit,-vml
Syntax:
-virtualmemorylimit value
Default:
-virtualmemorylimit 70
Category:
Advanced
Function:
Determines the limit on the available memory a component can utilise.
Before analysis is performed by a component a limit is set on the amount of memory that the component can utilise. By
default this limit is set to either a percentage of the systems physical memory or a default fixed size, whichever is largest.
This option determines the limit placed on the memory available to the component during analysis as a percentage of the
total systems memory.
If the argument of this option is 0 then no memory limit is applied to the component. And if the value of the argument does
not lie between 0 and 100 then the default limit will be applied.
