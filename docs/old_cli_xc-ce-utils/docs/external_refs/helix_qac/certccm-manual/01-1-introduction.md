1 | Introduction
This document provides an introduction to the CERTC Compliance Module (hereafter referred to as CERTCCM) that
was developed by PRQA to enforce compliance with the CERT C programming standard in conjunction with Helix QAC
for C. The module was created in accordance with the information contained in the 2016 Edition of the "SEI CERT C
Coding Standard", which was intended to facilitate the development of safe, reliable, and secure systems.
Note:
The SEI CERT C coding standard is updated on a continuous basis. Since the last edition ("SEI CERT C
Coding Standard", 2016 Edition) new rules have been introduced. This compliance module is based on
the SEI CERT C Coding Standard (28th April 2020). The rules are those in the last published edition
("SEI CERT C Coding Standard",2016 Edition) plus EXP47-C, ERR34-C, CON43-C, and MSC41-C.
The CERT C Secure Coding Standard was developed on the CERT Secure Coding wiki following a community-based
development process. It was developed specifically for versions of the C programming language defined by the
following:
n ISO/IEC 9899:2011 ISO/IEC, Programming Languages C, 3rd ed. [ISO/IEC 9899:2011]
n ISO/IEC 9899:2011/Cor.1:2012, Technical Corrigendum 1
Note:
Although the guidelines for this Standard were developed for C11, they can also be applied to earlier
versions of the C programming language, including C99.

CERT C Rules and Recommendations
The word guidelines encompasses both rules and recommendations. Rules are intended to provide normative
requirements for code, whereas recommendations are intended to provide guidance that, when followed, should improve
the safety, reliability and security of software systems.
For a guideline to be classified as a rule, it must meet the following criteria:
1. Its violation is likely to result in a defect that may adversely affect the safety, reliability, or security of a system, for
example, by introducing a security flaw that may result in an exploitable vulnerability.
2. It cannot rely on source code annotations or assumptions of Programmers’ intent.
3. Conformance to it can be determined using automated analysis (either static or dynamic), formal methods, or
manual inspection techniques.
Recommendations are suggestions for improving code quality. A guideline is defined as a recommendation when both of
the following conditions are met:

Note:
Both rules and recommendations are subject to change because the CERT C standard is open to
contributions from the community via the above-mentioned wiki. Recommendations in particular are
likely to change more frequently and, as a result, the names of recommendations included in CERTCCM
may not correspond directly to those on the wiki.
Enforcement of CERT C by Helix QAC for C
Helix QAC for C is a software tool that performs static analysis on C source code. It is important to have it configured so
as to restrict the output of warning messages to those that are of particular concern. Selection of the CERTCCM
component in your Helix QAC projects configures Helix QAC for C to enforce compliance with the CERT C coding
guidelines.
Helix QAC for C is able to detect most of the statically detectable conditions identified in the CERT C guidelines (as well
as many others). CERTCCM configures Helix QAC for C to identify issues that are specific to those guidelines, and
provides a cross-reference between the standard Helix QAC for C warning message(s) and the corresponding CERT C
rule or recommendation. Also available is an extended HTML description of each guideline.
For some CERT C coding guidelines that are not enforceable directly by Helix QAC for C, additional checks are provided
through CERTCCM secondary analysis. These checks are programmed using the analysis output files generated by the
Helix QAC for C primary analysis process.
Some CERT C guidelines impose constraints on the complete project rather than the code in a single translation unit.
These requirements are enforced by the Cross-Module Analysis capability of Helix QAC for C (enforced through the
RCMA component).
CERT C also includes guidelines pertaining to concurrency and parallelism. These requirements are enforced by the
Multi-Threading Analysis capability of Helix QAC for C (enforced through the MTA component).
