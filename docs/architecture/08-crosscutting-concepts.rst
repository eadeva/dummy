Crosscutting concepts
=====================

Configuration ownership and errors
----------------------------------

Each conventional document owns a section or named entity. Source locations
survive assembly so validation can identify an offending file and value.
Explicit CLI overrides, declared defaults and variant inheritance are model
operations; they do not introduce file precedence or arbitrary merging.
Unknown fields and unsupported layouts fail rather than invoking a migration
fallback.

Context and substitution
------------------------

Runtime templates resolve documented namespaces such as project, run, variant,
parameters, environment, Git and date. Discovery paths remain literal. Git
queries are local, lazy and cached within the relevant operation. The source
commit in a GitHub PR differs from the checked-out merge commit; both are
available explicitly. Untagged source commits have an empty exact tag value.

Isolation and trust
-------------------

A job environment starts from a filtered base and adds declared variables, PATH
entries, tool locations and selected Python runtime. Secret providers resolve
only needed values; PTK masks known secrets in its logging path. This cannot
prevent a project command from writing a secret directly to a file or
external service. Python tools and job commands execute with the user's permissions.

Concurrency and lifetime
------------------------

Parallel execution uses explicit scheduling limits. Run locks protect shared
job/variant storage. Background work has a finite owner and join boundary;
cooperative Python cancellation differs from process-tree termination. Output
cleanup validates all targets before deletion but is not transactional against
arbitrary filesystem failures.

Reporting and retention
------------------------

Canonical reports contain execution results, imported tool contributions and
log findings. Severity (warning/error) and disposition
(active/ignored/justified) are independent. Reports preserve raw evidence and
suppression reasons. Current plus three previous runs is the default retention;
configuration can change the backup count. A historical export uses retained
inputs rather than the newest job's files.

Compatibility
-------------

The schema and description protocol are generated by the installed PTK. Additive
model metadata can flow into generic clients; new widget semantics or protocol
changes may require client updates. Package resources are version aligned, but
that does not guarantee every independently installed extension/package pair is
compatible. No legacy configuration loader is retained.
